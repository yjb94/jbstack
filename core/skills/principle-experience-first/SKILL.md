# Experience First

구현 편의와 사용자 만족이 충돌하면 만족을 택한다.

- 모든 기능, 컨트롤, 옵션에는 정당한 이유가 있어야 한다
- 적게 내고 더 잘 낸다 (기능 세 개를 다듬은 경험이 거친 열 개보다 낫다)
- 확정하기 전에 프로토타입을 만든다 (설계 결정은 프로덕션 코드보다 버리는 HTML에서 더 싸다)
- 디테일을 맞춘다 (전환, 정렬, 간격, 피드백, 오류 상태)
- 핵심 루프를 조인다 (모든 기능은 중심 워크플로에 기여하거나 비켜서야 한다)

사용자는 작업의 결과물을 쓰는 모든 사람이다. UI라면 최종 사용자다. 라이브러리나 내부 API라면 그것을 import하는 동료다. 다음에 그 코드를 유지보수할 엔지니어도 사용자다. 그들의 경험도 같은 비중으로 따지고, 영향은 그들의 관점에서 설명한다.

기반은 경험을 뒷받침해야 한다. Foundational Thinking은 작업의 *순서*를 다룬다. 이 원칙은 *목표*를 다룬다.
