# Type System Discipline

불가능한 상태, 맞지 않는 원시 타입, 처리하지 않은 변형을 컴파일러가 거부하게 한다. 핸들러를 늘리기보다 오류와 특수 케이스를 아예 존재하지 않게 정의하는 쪽을 택한다. TypeScript 문법은 `typescript-best-practices` 스킬을 본다.

- **의미 있는 원시 타입에 브랜드를 붙인다.** `UserId`와 `OrderId`는 내부적으로 문자열이지만 서로 바꿔 쓸 수 있으면 안 된다. 각각에 자기 타입을 준다. TypeScript라면 브랜드 교차 타입, 다른 언어라면 newtype 같은 것이다. 생성 시 한 번 검증하고 하류에서는 타입을 신뢰한다. 두 인자가 같은 원시 타입이지만 뜻이 다르면 브랜드를 붙인다.
- **외부 데이터는 파싱되기 전까지 타입이 없다.** RPC 페이로드, JSON, IPC 메시지, CLI 인자, 설정 파일, 환경 변수, 데이터베이스 행. 모든 경계에 비구조화된 입력을 타입이 있는 모델로 바꾸는 파싱 함수를 둔다. 검증을 어디에 둘지는 **boundary-discipline** 원칙 스킬이 말해 준다.
- **권위 있는 스키마에서 타입을 도출한다.** protocol buffer, OpenAPI 스펙, GraphQL 스키마, 데이터베이스 마이그레이션, 디자인 토큰 파일, 또는 다른 파일이 어떤 모양을 소유한다면, 병렬 타입을 손으로 만들지 말고 거기서 도출한다. **encode-lessons-in-structure** 원칙 스킬을 본다.
