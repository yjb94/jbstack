# Prove It Works

모든 작업 산출물은 실제 대상을 직접 확인해서 검증한다. 간접 지표, 자기 보고, "컴파일된다"로 추론하지 않는다.

**이유:** 검증되지 않은 작업은 정확성을 알 수 없다. 간접 검증(파일 mtime, 출력의 신선함, 에이전트의 자기 보고, 캐시된 스크린샷)은 직접 관찰보다 싸게 느껴진다. 잘못된 추론에 따라 행동하는 비용은 원본을 확인하는 비용보다 훨씬 크다.

간접 지표가 아니라 실제 대상을 확인한다.
- 프로세스가 살아 있는지는 파생 상태를 거치지 말고 직접 확인한다
- 캐시되거나 파생된 표현이 아니라 실제 값을 읽는다
- 검증이 실패하면 시스템을 의심하기 전에 관찰 방법을 의심한다

## Script the check when you can

가장 강한 증거는 같은 비교를 다시 실행하는 결정적 스크립트다. 한 번 눈으로 보는 것이 아니다. 스크립트를 쓰고, 실행하고, 그 출력을 리뷰어가 당신의 말을 믿는 대신 직접 다시 실행해 볼 수 있는 산출물로 남긴다.

산출물은 사람이 볼 수 있게 둔다. 큰 포팅이나 마이그레이션처럼 나중에 기록을 감사할 수 있어야 하는 크고 복잡한 작업에서만 커밋한다 (**show-me-your-work** 스킬).
